# Fix: Browse Button Shows JS Prompt Instead of Folder Picker

## Problem

The "Browse" button in `DeployPortfolioDialog.razor` uses `JSRuntime.InvokeAsync("prompt")` which shows a plain JavaScript text input popup, not a real OS folder explorer dialog.

## Root Cause

Blazor Server runs on the server, not the browser. Browser security prevents JavaScript from accessing the absolute file system path. The `prompt()` call was a placeholder.

## Solution

Use a hidden `<input type="file" webkitdirectory>` element. This:
1. Opens the **real OS folder picker dialog** (native Windows Explorer folder picker on Windows)
2. Returns the selected files with their relative paths (`webkitRelativePath`)
3. We show the user what files were found as confirmation
4. The user still types the full absolute path (browser security limitation), but they've visually confirmed the folder contents

**Note:** This is the standard web approach. True native path access would require Blazor Desktop/MAUI, which is out of scope.

## Files to Modify

- `src/Certus.Dashboard/Components/Shared/DeployPortfolioDialog.razor` — replace JS prompt with hidden `<input webkitdirectory>` + JS interop

## Implementation

1. Add a hidden `<InputFile>` element with `webkitdirectory` attribute
2. Add an `OnChange` handler that reads the selected files
3. Show the files found (names + count) as confirmation
4. Pre-fill the folder path text field with the first file's relative folder name as a hint
5. Remove the `JSRuntime.InvokeAsync("prompt")` call

## Verification

- Click Browse → real OS folder picker opens
- Select a folder with .ex4 files → files are listed in the UI
- User can then type/correct the full path in the text field

## Implementation Plan

### Gap 1: FileSystemWatcher not started after deployment (FR-008, NFR-003, AC-015, AC-021, AC-022)

**Problem**: `DeployAsync` calls `deployment.StartMonitoring()` which only changes the DB status. No actual `FileSystemWatcher` is created on the Certus directory. The existing `FileImportService` has watcher infrastructure but it's wired to `PlatformService`, not deployment.

**Fix**: After deployment succeeds, start file monitoring via `IFileImportService` on the Certus output directory. Wire deployment start/stop to the file watcher.

**Files**:
- `src/Certus.Application/Platform/PortfolioDeploymentService.cs` — inject `IFileImportService`, call `StartWatching` after deployment
- `src/Certus.Application/Platform/PortfolioDeploymentService.cs` — call `StopWatching` in `StopMonitoringAsync`

### Gap 2: PortfolioDeploymentId missing on PlatformConnection (FR-009)

**Problem**: Spec requires `PlatformConnection.PortfolioDeploymentId : Guid?` but the entity doesn't have it.

**Fix**: Add the field to PlatformConnection, update EF configuration, create migration.

**Files**:
- `src/Certus.Domain/Platform/Aggregates/PlatformConnection.cs` — add `Guid? PortfolioDeploymentId` property + setter
- `src/Certus.Infrastructure/Persistence/Configurations/Platform/PlatformConnectionConfiguration.cs` — configure new column
- `src/Certus.Infrastructure/Migrations/` — new migration
- `src/Certus.Application/Platform/PortfolioDeploymentService.cs` — set the field during deployment

### Gap 3: No folder picker dialog (FR-001, AC-001)

**Problem**: The UI only has a manual text input. Spec says "folder picker dialog or manual path input" and AC-001 specifically says "when the folder picker opens, then the user can browse and select".

**Fix**: Add a "Browse" button that opens an OS folder picker. On Blazor Server, this requires a JS interop or the approach of using a hidden input element. Since Blazor Server can't directly access the file system, use a JavaScript interop approach with `<input type="file" webkitdirectory>` to pick folders.

**Files**:
- `src/Certus.Dashboard/Components/Shared/DeployPortfolioDialog.razor` — add Browse button + JS interop for folder selection
- `src/Certus.Dashboard/wwwroot/js/` (or inline script) — folder picker JS interop

### Gap 4: No deployment logging (FR-012, AC-012 partial)

**Problem**: `PortfolioDeploymentService` has zero logging. No `ILogger` injected.

**Fix**: Inject `ILogger<PortfolioDeploymentService>` and add structured log calls at key points.

**Files**:
- `src/Certus.Application/Platform/PortfolioDeploymentService.cs` — inject ILogger, log: validation results, file copy (each file: copied/skipped), monitoring start/stop, errors

### Gap 5: CertusManager.mq4 not deployed (FR-013, AC-018, AC-019)

**Problem**: `ActivateEAsAsync` writes `certus_activation.json` but never copies any management script to `MQL4/Scripts/`. The CertusManager.mq4 file itself doesn't exist in the repo.

**Fix**: Create the CertusManager.mq4 script as a resource file, copy it during activation.

**Files**:
- `src/Certus.Dashboard/Resources/` or `src/Certus.Infrastructure/Resources/` — add `CertusManager.mq4`
- `src/Certus.Application/Platform/PortfolioDeploymentService.cs` — copy script to Scripts/ directory during activation

### Gap 6: No existing deployment warning (AC-008)

**Problem**: When a user selects a connection that already has a deployment, there's no warning shown.

**Fix**: In `CheckConflictsAndNext()` or when connection is selected, check `IPortfolioDeploymentRepository.GetByConnectionIdAsync()` and show warning.

**Files**:
- `src/Certus.Application/Platform/IPortfolioDeploymentService.cs` — add `Task<bool> HasExistingDeploymentAsync(Guid connectionId)`
- `src/Certus.Application/Platform/PortfolioDeploymentService.cs` — implement it
- `src/Certus.Dashboard/Components/Shared/DeployPortfolioDialog.razor` — show warning in Step 2

### Gap 7: No progress tracking in dialog (FR-010, AC-010)

**Problem**: Step 4 shows an indeterminate spinner. Spec says "Progress bar showing copy status" and "Copying X files to MT4...".

**Fix**: This is a UI-only issue. The deployment is synchronous so a real progress bar requires either:
- Making deployment async with a progress callback, or
- Simulating progress based on file count (pragmatic approach)
For now, at minimum show "Copying X of Y files..." text. A real progress bar would require SignalR/async approach.

**Files**:
- `src/Certus.Dashboard/Components/Shared/DeployPortfolioDialog.razor` — update status text in Step 4

### Gap 8: No last data timestamp on deployment cards (AC-023)

**Problem**: Deployment cards don't show when data was last received.

**Fix**: Add `LastDataReceivedAt` to `PortfolioDeploymentDto`, populate it from `IFileImportService.GetLastModifiedTime(connectionId)`.

**Files**:
- `src/Certus.Application/Platform/DTOs/PortfolioDeploymentDto.cs` — add `DateTime? LastDataReceivedAt`
- `src/Certus.Application/Platform/PortfolioDeploymentService.cs` — inject IFileImportService, populate field in MapToDtoAsync
- `src/Certus.Dashboard/Components/Pages/PlatformDashboard.razor` — display last data timestamp
