# Scale: Trade Import Pipeline — Handle Large Files Efficiently

## Context

The trade import pipeline works correctly but has scalability concerns:
1. `trades.json` is append-only and grows unbounded (EA appends every trade event)
2. On every file change, the entire file is read, parsed, and each trade is individually queried against the DB
3. On startup, the entire file is re-imported
4. With thousands of records, this means: multi-MB file reads, full JSON parse, 1000+ individual DB queries per import

## Current Flow (per file change)

```
FileChanged event
  → ReadFileAsync (reads ENTIRE file — could be MBs)
  → ParseTrades (parses ALL lines — O(n))
  → GroupBy ExternalId, dedup (in-memory — fine)
  → FOR EACH deduped trade:
      → GetByExternalIdAsync (individual DB query — N+1!)
  → SaveChangesAsync
```

## Plan

### Step 1: Incremental file read — only read new content

**File:** `src/Certus.Infrastructure/Platform/FileImportService.cs`

Add a `Dictionary<string, long> _fileOffsets` to track the byte position of the last successful read per file. On change:
- Open file, seek to `_fileOffsets[filePath]`, read only new bytes
- If the file was truncated (new position < old offset), reset to 0 and read everything
- Return only the new lines (content delta)

Add new method to `IFileImportService`:
```csharp
Task<string?> ReadNewContentAsync(string filePath);
```

`ReadFileAsync` (existing) stays for full reads. `ReadNewContentAsync` is used by the auto-import path.

Implementation:
- `_fileOffsets[filePath] = 0` on first read
- On subsequent reads: `stream.Seek(offset, SeekOrigin.Begin)`, read to end
- Update `_fileOffsets[filePath] = stream.Position` after successful read
- If new content is empty (no new lines), return null → skip import
- On file truncation (length < offset): reset offset to 0, full re-read

### Step 2: Batch DB lookups — eliminate N+1 queries

**File:** `src/Certus.Domain\Platform\Repositories\IImportedTradeRepository.cs`

Add new method:
```csharp
Task<IReadOnlyList<ImportedTrade>> GetByExternalIdsAsync(IEnumerable<string> externalIds);
```

**File:** `src\Certus.Infrastructure\Persistence\Repositories\Platform\ImportedTradeRepository.cs`

Implement with a single `WHERE ExternalId IN (...)` query:
```csharp
public async Task<IReadOnlyList<ImportedTrade>> GetByExternalIdsAsync(IEnumerable<string> externalIds)
{
    return await _db.ImportedTrades.AsNoTracking()
        .Where(t => externalIds.Contains(t.ExternalId))
        .ToListAsync();
}
```

**File:** `src\Certus.Application\Platform\PlatformService.cs`

Replace the N+1 loop in `ImportFromChangeAsync`:
```csharp
// Before: individual queries
foreach (var platformTrade in deduped)
{
    var existingTrade = await _tradeRepo.GetByExternalIdAsync(platformTrade.ExternalId);
    ...
}

// After: batch query, then process in memory
var externalIds = deduped.Select(t => t.ExternalId).ToList();
var existingTrades = await _tradeRepo.GetByExternalIdsAsync(externalIds);
var existingByExternalId = existingTrades.ToDictionary(t => t.ExternalId);

foreach (var platformTrade in deduped)
{
    if (existingByExternalId.TryGetValue(platformTrade.ExternalId, out var existingTrade))
    {
        // Update logic (unchanged)
        ...
        continue;
    }
    // Insert logic (unchanged)
    ...
}
```

This reduces DB queries from O(n) to O(1) per import.

### Step 3: Startup optimization — skip already-imported trades

**File:** `src\Certus.Infrastructure\Platform\ConnectionWatcherService.cs`

On startup, instead of doing a full `ImportFromChangeAsync` (which re-parses the entire file), do a targeted reconciliation:
1. Load all existing `ExternalId`s from DB into a HashSet (single query)
2. Read the file, parse, dedup
3. Only process trades NOT in the HashSet (new inserts) or with stale close data (updates)

This avoids redundant work on restart — most trades are already imported.

**File:** `src\Certus.Application\Platform\PlatformService.cs`

Add a new method `ReconcileTradesAsync(Guid connectionId, string filePath)` that:
1. Gets all existing ExternalIds for this connection: `SELECT ExternalId FROM ImportedTrades WHERE ConnectionId = @id`
2. Reads + parses + dedupes the file
3. Skips trades that are already in the DB AND already closed (CloseTime != null)
4. Only inserts new trades or updates open trades that now have close data

This is distinct from `ImportFromChangeAsync` which is the per-change handler. `ReconcileTradesAsync` is the startup/batch path.

### Step 4: Guard against unbounded file growth

**File:** `src\Certus.Application\Platform\PlatformService.cs`

In `ImportFromChangeAsync`, add a safety limit: if the file has more than N lines (e.g., 10,000), log a warning and only process the last M lines (e.g., last 5,000). This prevents OOM on extremely large files.

The EA should ideally rotate `trades.json` periodically (e.g., daily or after N trades), but that's an EA-side concern.
