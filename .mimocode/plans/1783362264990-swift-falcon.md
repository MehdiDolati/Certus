# Plan: Dashboard Real Data & Spec + GitHub Issue

## Context

The Certus Dashboard UI currently has several gaps where data is hardcoded, missing, or not wired up:

1. **Home page** (`Home.razor`) is just a static landing with a "View Portfolios" button — no data at all
2. **NavMenu** only links Home and Portfolios — no Platform/Connections link
3. **`TradeService`** hardcodes `StrategyName` to `string.Empty` (line 38, 63) and `PortfolioImpact`/`StrategyImpact` to `0m` (line 78)
4. **Platform connections** have a full service layer (`PlatformService.GetDashboardAsync()`) but zero UI pages
5. **ImportedTrades** are not visible anywhere in the UI
6. **PortfolioDetail** hardcodes the initial period to 30 days regardless of the dropdown selection

The services already query the DB correctly — the issue is the UI layer not surfacing the data properly.

---

## Spec: `specs/features/dashboard-real-data.md`

Create a new spec file covering:

- **FR-001**: Home page shows real overview KPIs (total portfolios, total trades, total PnL, active connections, platform health) from DB
- **FR-002**: Home page shows recent trades table (last 10 imported trades) from `ImportedTradeRepository`
- **FR-003**: Home page shows platform connection status cards
- **FR-004**: NavMenu includes Platform link (`/platform`)
- **FR-005**: Platform page (`/platform`) shows connection list, total imported trades, total PnL from `PlatformService.GetDashboardAsync()`
- **FR-006**: Fix `TradeService` to resolve `StrategyName` from `IStrategyDefinitionRepository` instead of hardcoding empty string
- **FR-007**: Fix `TradeService.GetTradeDetailAsync()` to compute `PortfolioImpact` and `StrategyImpact` from actual trade data
- **FR-008**: PortfolioDetail initial period uses the dropdown selection (not hardcoded 30 days)

## Implementation Plan

### Step 1: Fix `TradeService` hardcoded values
**Files**: `src/Certus.Application/Trading/TradeService.cs`

- Inject `IStrategyDefinitionRepository` into `TradeService`
- In `GetTradesAsync()` and `GetTradeDetailAsync()`: resolve `StrategyName` by looking up the strategy from the repository using `t.StrategyId`
- In `GetTradeDetailAsync()`: compute `PortfolioImpact` as the sum of PnL for all trades in the same portfolio, and `StrategyImpact` as the sum of PnL for all trades in the same strategy

### Step 2: Enhance Home page with real overview data
**Files**: 
- `src/Certus.Dashboard/Components/Pages/Home.razor`

- Inject `IPortfolioService`, `IPlatformService`, `ITradeService`, `IImportedTradeRepository` (via a new `IPlatformDashboardService` or directly)
- Display KPI cards: Total Portfolios, Total Trades (from both `Trade` and `ImportedTrade`), Active Strategies, Platform Connections
- Show recent imported trades (last 10) in a small table
- Show platform connection status indicators

### Step 3: Create Platform page
**Files**:
- `src/Certus.Dashboard/Components/Pages/PlatformDashboard.razor` (new)

- Route: `/platform`
- Inject `IPlatformService`
- Call `GetDashboardAsync()` to get connections, total trades, total PnL
- Show connection status cards (name, status, last data received)
- Show aggregate stats: total imported trades, total PnL, active connections count

### Step 4: Update NavMenu
**Files**: `src/Certus.Dashboard/Components/Layout/NavMenu.razor`

- Add Platform nav link with icon

### Step 5: Fix PortfolioDetail period handling
**Files**: `src/Certus.Dashboard/Components/Pages/PortfolioDetail.razor`

- On initial load, use the default selected period instead of hardcoding `Last30Days`
- Pass period to both `GetPortfolioDetailAsync()` and `GetCumulativePnlAsync()`

### Step 6: Register new services in DI
**Files**: `src/Certus.Infrastructure/DependencyInjection.cs`

- Ensure `IImportedTradeRepository` is available to the dashboard (already registered)

### Step 7: Update SPEC.md index
**Files**: `SPEC.md`

- Add link to new `specs/features/dashboard-real-data.md`
