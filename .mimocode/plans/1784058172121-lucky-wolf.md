## Gaps to Fix

### Gap 1: `PlatformDataRepository` is a STUB
**File**: `src/Certus.Infrastructure/Persistence/Repositories/Platform/PlatformDataRepository.cs`

All 6 methods return null/empty. This means the **explicit import flows** (`ImportPortfolioAsync`, `ImportTradesAsync`, `GetStrategiesAsync`) in `PlatformService` always return null or empty results. Only the auto-import path (file watcher → `AutoImportFromChangeAsync`) works because it reads files directly.

**What needs to happen**: The `PlatformDataRepository` needs to actually store and retrieve `PlatformPortfolio`, `PlatformStrategy`, and `PlatformTrade` snapshots. Options:
1. **Store in DB tables** — create EF Core entities for `PlatformPortfolioSnapshot`, `PlatformStrategySnapshot`, `PlatformTradeSnapshot` and implement the repository with queries
2. **Store in memory** (simpler) — use `IConnectionStatusStore` pattern with in-memory dictionaries keyed by `(connectionId, externalId)`

### Gap 2: `DeviationCalculator` Not Wired Into Import Flow
**File**: `src/Certus.Application/Platform/DeviationCalculator.cs`

The `DeviationCalculator` exists but is never called. FR-007 says: "Calculate deviations from expected behavior by comparing actual vs expected trade outcomes." The `ImportTradesResult` should include deviation data, or the `AutoImportFromChangeAsync` should calculate deviations after importing trades.

**What needs to happen**: After trades are imported (in `ImportTradesAsync` or `AutoImportFromChangeAsync`), call `DeviationCalculator.CalculateTradeDeviation()` if expected outcomes are available. Add deviation results to `ImportTradesResult`.

### Gap 3: No Automatic Reconnection Logic
**Files**: `PlatformService.cs`, `ConnectionStatus.cs`

BR-005 says: "Platform connection status transitions: Disconnected → Connecting → Connected, Connected → Error → Reconnecting → Connected"
BR-006 says: "After 5 consecutive errors, the connection stops retrying"

Currently, `CheckStaleness()` detects stale/missing files and transitions to `Error` state, but there's no automatic reconnection retry. The `ConnectionStatus.WithError()` increments `RetryCount`, and `ShouldReconnect` (per spec) should return false at 5 — but neither reconnection nor the `ShouldReconnect` check exists.

**What needs to happen**: Add a background timer or hook into `CheckStaleness()` that attempts reconnection when status is `Error` and `RetryCount < 5`. Transition through `Reconnecting` state.

3. Implement state transitions: Error → Reconnecting → Connected
