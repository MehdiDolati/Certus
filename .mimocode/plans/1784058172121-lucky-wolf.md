# Plan: Implement EF Core Migrations

## Problem
`Program.cs` (lines 30-37) runs `EnsureDeletedAsync()` then `EnsureCreatedAsync()` on every startup in Development. This destroys all data each time. No EF Core migrations exist — the schema is recreated from scratch every run.

## Approach
Switch to EF Core code-first migrations. Create an initial migration, apply it on startup, and preserve seed data logic.

## Files to Modify

### 1. `src/Certus.Infrastructure/Certus.Infrastructure.csproj` — add Design-time DbContext factory
Add a `DesignTimeDbContextFactory` so `dotnet ef` CLI tool works (it needs a way to instantiate the DbContext without the DI container). This is a new file + csproj reference.

### 2. New: `src/Certus.Infrastructure/Persistence/DesignTimeDbContextFactory.cs`
EF Core design-time factory that reads the connection string from configuration and creates `CertusDbContext` for `dotnet ef migrations` commands.

### 3. `src/Certus.Dashboard/Program.cs` — replace EnsureDeleted/EnsureCreated with Migrate
Replace lines 30-37:
```csharp
// BEFORE (development only)
if (app.Environment.IsDevelopment())
    await db.Database.EnsureDeletedAsync();
await db.Database.EnsureCreatedAsync();
await SeedData.SeedAsync(db);

// AFTER
await db.Database.MigrateAsync();
await SeedData.SeedAsync(db);
```
- `MigrateAsync()` applies any pending migrations (or is a no-op if DB is up to date)
- Seed data only inserts if the DB is empty (already guarded by `AnyAsync` check in `SeedData.SeedAsync`)
- Works in both Development and Production

### 4. Generate initial migration
Run `dotnet ef migrations add InitialCreate` to scaffold the initial migration from the existing model. This captures the current schema as a migration file.

### 5. `tests/Certus.IntegrationTests/CustomWebApplicationFactory.cs` — no changes needed
Tests use in-memory SQLite with `EnsureCreated()` which is correct for tests (migrations target SQL Server; SQLite in tests doesn't need them).

## Verification
1. `dotnet ef migrations add InitialCreate --project src/Certus.Infrastructure --startup-project src/Certus.Dashboard` — generates migration
2. `dotnet build` — confirms no compilation errors
3. Start the app — DB is created via migration, seed data is applied
4. Stop and restart — DB is NOT recreated, seed data is NOT re-inserted (idempotent)
5. Run integration tests — still pass (unaffected by migration changes)
