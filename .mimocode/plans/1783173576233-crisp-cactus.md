# Certus Domain Architecture Restructuring Plan

## Overview

Restructure the existing Clean Architecture monolith into 6 bounded contexts that map to the 6 autonomous agent modules. Big-bang approach — restructure everything in one focused effort, then fix all tests.

## Key Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Portfolio + Strategy | Separate aggregates in separate contexts | Different lifecycle, different agent ownership, cleaner extraction later |
| Trade aggregate | Independent root in Execution context | Owns its complex lifecycle, references Portfolio/Strategy by ID |
| PerformanceSnapshot | Child of PerformanceReport in Evaluation | Snapshots always consumed as part of a report |
| Coordination context | Lightweight placeholder | Flesh out as other contexts are built |
| Migration | Big-bang restructuring | Faster, all tests fixed in one pass |
| Cross-context comms | In-process domain events (Phase 1) | Swappable to message bus later without changing event classes |
| DbContext split | After MVP | Keep shared DbContext until all contexts have real logic, then split at once |

## Implementation Steps

### Step 1: SharedKernel Foundation
- Create `Domain/SharedKernel/` folder
- Implement `Entity`, `AggregateRoot`, `IDomainEvent`, `IDomainEventHandler`, `IDomainEventDispatcher`
- Implement `Money`, `Symbol`, `Currency`, `AssetClass` value objects
- Move `ValueObject`, `DateRange`, `PaginatedResult` from `Shared/` to `SharedKernel/`
- Delete old `Shared/` and `Events/` folders

### Step 2: Big-Bang Context Restructuring
- Create all 6 context folders under `Domain/`
- Move entities to target contexts (Portfolio→RiskAndPortfolio, Strategy→Strategy, Trade→Execution, PerformanceSnapshot→Evaluation)
- Rename `Strategy` to `StrategyDefinition`, update `StrategySlot` as portfolio assignment
- Move repository interfaces to context-specific Repositories/ folders
- Move enums to context-specific Enums/ folders
- Update ALL namespaces across Domain, Application, Infrastructure layers

### Step 3: New Entities & Value Objects per Context
- Market: `MarketDataSeries`, `Signal`, `PriceBar`, `SignalStrength`, `TimeFrame`, etc.
- Strategy: `StrategyParameter`, `BacktestRun`, `BacktestTrade`, `StrategySlot`, `StrategyType`, `BacktestConfig`, `BacktestMetrics`, `Weight`, `RiskProfile`, `ConfidenceInterval`
- RiskAndPortfolio: `RiskLimit`, `AllocationRule`, `RiskAssessment`, `CapitalAllocation`, `DrawdownLimit`, `PositionLimit`, `VaRMetric`, `AllocationTarget`, `AdaptiveRiskParams`
- Execution: `Order`, `Fill`, `ExecutionLog`, `OrderRequest`, `ExecutionResult`, `SlippageMetrics`, `TradeLifecycle`, `OrderType`, `OrderStatus`, `ExecutionVenue`
- Evaluation: `PerformanceReport`, `BenchmarkComparison`, `StrategyEvaluation`, `FeedbackEntry`, `ReturnMetrics`, `RiskMetrics`, `TradeMetrics`, `BenchmarkResult`, `EvaluationScore`
- Coordination: `AgentTask`, `SystemHealth`, `AgentState`, `TaskDependency`, `CoordinationCycle`, `AgentId`, `TaskPriority`, `CycleMetrics`, `HealthStatus`

### Step 4: Domain Events
- Implement events for all 6 contexts (30+ events total)
- Each context publishes events it owns, subscribes to events from other contexts
- Phase 1: synchronous in-process dispatch within same transaction

### Step 5: Enrich Existing Entities
- Portfolio: add `RiskLimits[]`, `AllocationRules[]`, `AdaptiveRiskParams`, `MarketRegime`
- StrategyDefinition: add `StrategyType` (value object replaces string), `StrategyParameter[]`, `BacktestRun[]`, `RiskProfile`, `StrategySlot[]`
- Trade: add `Order[]`, `ExecutionLog[]`, `TradeLifecycle` value object, extended `TradeStatus`

### Step 6: Application Layer
- Create UseCase interfaces and implementations per context
- Create DTOs per context
- Move existing DTOs to new context folders
- Implement `InProcessDomainEventDispatcher`
- Implement event handlers for cross-context communication
- Update `DependencyInjection.cs`

### Step 7: Infrastructure Layer
- Create EF configurations for all new entities per context folder
- Create repository implementations per context folder
- Extend `CertusDbContext` with new DbSets
- Update seed data for new entities
- Update `DependencyInjection.cs` registrations

### Step 8: Update Tests
- Fix all namespace references in existing tests
- Add architecture tests for context boundary enforcement
- Add domain tests for new entities and value objects
- Add application layer tests for new use cases
- Add integration tests for new repositories
- Verify all ~73+ tests pass

### Step 9: Dashboard Updates
- Update service references if interface names changed
- Add placeholder pages for Market, Strategy, Coordination views
- Verify existing Portfolio/Strategy/Trading views still work
