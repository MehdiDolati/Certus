# Refactor: Extract Connection Status from DB to In-Memory Store

## Problem
Connection status (Connected, Disconnected, Error, etc.) is ephemeral runtime state persisted to the DB unnecessarily. This forces `SaveChangesAsync` calls on every status change, creates stale records, and complicates the code.

## Goal
- **DB stores**: connection config only (platform, file path, settings)
- **In-memory stores**: live status (connected, lastDataReceived, retryCount, error)
- Reduce `SaveChangesAsync` calls to config-only operations

## Design

### 1. New Domain Interface: `IConnectionStatusStore`

**File:** `src/Certus.Domain/Platform/Interfaces/IConnectionStatusStore.cs`

```csharp
public interface IConnectionStatusStore
{
    ConnectionStatus Get(Guid connectionId);
    void Set(Guid connectionId, ConnectionStatus status);
    void Remove(Guid connectionId);
}
```

### 2. New Value Object: `ConnectionStatus`

**File:** `src/Certus.Domain/Platform/ValueObjects/ConnectionStatus.cs`

```csharp
public record ConnectionStatus
{
    public PlatformConnectionStatus State { get; init; } = PlatformConnectionStatus.Disconnected;
    public DateTime? ConnectedAt { get; init; }
    public DateTime? LastDataReceivedAt { get; init; }
    public string? ErrorMessage { get; init; }
    public int RetryCount { get; init; }
}
```

### 3. New Infrastructure: `InMemoryConnectionStatusStore`

**File:** `src/Certus.Infrastructure/Platform/InMemoryConnectionStatusStore.cs`

- Singleton, uses `ConcurrentDictionary<Guid, ConnectionStatus>`
- Simple get/set/remove

### 4. Simplify `PlatformConnection` Aggregate

**File:** `src/Certus.Domain/Platform/Aggregates/PlatformConnection.cs`

Remove from the aggregate:
- `Status`, `ConnectedAt`, `DisconnectedAt`, `LastDataReceivedAt`, `ErrorMessage`, `RetryCount`
- `Connect()`, `Disconnect()`, `SetError()`, `StartReconnecting()`, `UpdateLastDataReceived()`, `ShouldReconnect()`

Keep:
- `Id`, `PlatformId`, `PlatformName`, `Config`
- `Create()` factory (simplified)

### 5. Update `PlatformService`

**File:** `src/Certus.Application/Platform/PlatformService.cs`

- Inject `IConnectionStatusStore` alongside existing dependencies
- `ConnectAsync`: write config to DB, write status to in-memory store
- `DisconnectAsync`: update status in memory (no DB save needed for status)
- `GetDashboardAsync`, `GetConnectionsAsync`: compose DTO from DB config + in-memory status
- Remove all `SaveChangesAsync` calls that were for status changes (keep only for config inserts)

### 6. Update Repository

**File:** `src/Certus.Infrastructure/Persistence/Repositories/Platform/PlatformConnectionRepository.cs`

- Remove `GetByStatusAsync` (no longer needed — status is in memory)
- Remove `SaveChangesAsync` from interface (repo shouldn't own persistence boundary)
- Keep `AddAsync`, `GetAllAsync`, `GetByIdAsync`, `GetByPlatformAndPathAsync`, `Update`

### 7. Update EF Configuration

**File:** `src/Certus.Infrastructure/Persistence/Configurations/Platform/PlatformConnectionConfiguration.cs`

- Remove `Status`, `ErrorMessage` column configs
- Remove `OwnsOne` for Config if it was storing status-related columns
- Keep platform, name, config mapping

### 8. Update DTOs

**Files:** `src/Certus.Application/Platform/DTOs/`

- `PlatformConnectionDto`: unchanged (still has Status, ConnectedAt, etc.)
- `PlatformStatusDto`: unchanged
- These are now populated from in-memory store, not DB

### 9. Update Dashboard

**File:** `src/Certus.Dashboard/Components/Pages/PlatformDashboard.razor`

- No changes needed — it reads from DTOs which are composed by the service

### 10. Register in DI

**File:** `src/Certus.Infrastructure/DependencyInjection.cs`

- Add: `services.AddSingleton<IConnectionStatusStore, InMemoryConnectionStatusStore>()`
